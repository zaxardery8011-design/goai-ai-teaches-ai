# 2. 每一步要可驗收

「做完了」不是驗收。驗收是一個外人看得到的條件：檔在、長度夠、命令結束碼、欄位對得上、人聽得懂要對哪一段。

沒有驗收的步驟，模型會把「我覺得可以」當成完成。

## 做法

每一步在技能裡寫死成功長什麼樣子。例如：

- 摘要檔存在，且大於 200 位元組，四個區塊齊。
- GitHub 回傳的 canonical 名稱等於宣稱的擁有者／專案名。
- 訓練集筆數等於清單筆數，否則停。
- 試聽一次一份，每段標模型名。
- 個資掃描 0 命中；同一指令掃對照組有命中。

說 ok 之後再打開檔看一眼。回傳物件說成功、檔是空的，這種事發生過。

## 真實例子（去識別）

影片消化管線回一個物件，欄位叫成功。真正收工條件是：那個欄位為真，**而且**產出路徑存在、長度超過 200 位元組。少後兩項，會把空檔當成品。

語音微調有一輪，前置檢查 GPU 可用，套件 import 卻缺漏。GPU 亮著不等於可以訓練。後來把前置檢查寫成「指定模組全部 import 成功才算過」，才進得了下一刀。

再一輪：訓練程式要求 81／81，實際 79／81，在存檔前丟錯。若沒有「筆數對得上才算成功」，會以為跑過就是練過。那一輪沒有權重。
