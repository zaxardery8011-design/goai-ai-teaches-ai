# 3. 先查成熟做法再動手

開源生態已經有解的題，第一個動作是去程式託管網站找現成專案、README、issue。不是在本機發明第 N 輪試驗。

自己試不是禁令。自己試之前要知道別人卡在哪。issue 裡寫過的依賴衝突，你會再踩一次。

## 做法

1. 用關鍵詞搜成熟專案（星數當線索，仍要抽驗，見第 5 條）。
2. 讀 README 的硬體、授權、已知限制。
3. 打開相關 issue：安裝失敗、特定顯示卡、特定語言。
4. 選一條路，寫進檔。
5. 本機只跑這條。要換就整條換。

## 真實例子（去識別）

克隆自己的聲音時，連續三輪本機試聽。素材指到舊資料夾，新的朗讀沒被用到。每輪試聽檔段數不同，人無法對題。後來的指示是：這種題先查託管網站上的成熟做法，再依結論只跑一條；試聽一次一份。

台灣華語底模那條，環境卡在套件鎖與缺少現成 wheel。這是 issue 等級的問題。先查再裝，會少掉「連修三輪依賴才發現某套件沒有對應版本」的時間。查了仍可能要修，但修的是已知缺口，不是盲試。
