# skill-maker

技能包是給 AI 的教材。人把一次做對的流程寫進檔，下一輪換一個 AI 進來，讀檔就會做。這就是「用 AI 教導 AI」在日常裡的形狀。

公開格式用一份 `SKILL.md`：開頭一小段 YAML（名稱、何時觸發），正文寫步驟與驗收。這份說明寫的是我們實際在用的做法。官方技能格式若有更新，以各家文件為準，步驟精神不變。

## 何時用

手上已經有一次成功（或清楚失敗）的流程：命令、順序、產出、翻車點。要把它變成可重用的教材。

只有一個願望、還沒跑過，先去跑，再回來寫。沒跑過的流程寫成技能，會把猜測教給下一輪。

## 五步

### 1. 從實跑抓意圖

先從對話與產出裡抽出答案，再問缺口：

- 這份技能要讓 AI 做成什麼？
- 使用者會講哪幾句話觸發它？
- 產出長什麼樣子？
- 怎樣叫失敗？

他講「幫我做成 skill」時，先重述你聽到的流程給他確認，再動筆。

### 2. 寫 SKILL.md

資料夾最小形狀：

```
<技能名>/
  SKILL.md
  references/     可選，長資料、公式、表格
  scripts/        可選，重複且不該每次讓模型重寫的動作
```

YAML：

- `name`：短、小寫、連字號。
- `description`：同時寫「做什麼」與「何時用」。觸發全寫在這裡。模型偏於少觸發，描述寫清楚場合，含使用者會講的口語。

正文用祈使句。固定產出就給模板。每一步寫驗收：檔在不在、長度、命令結束碼、打開頁面看得到什麼。

本機才有的工具，寫替代：

> 你的環境若沒有 X，用 Y。Y 做不到就停，回報缺什麼。

不要把某一台機器的絕對路徑寫進去。落點問使用者。

### 3. 紅線與範圍

技能裡寫清：

- 何時不要用（相鄰任務走哪一份）。
- 什麼能改、什麼只能讀。
- 失敗怎麼講。禁止假裝成功。

技能內容不應讓使用者感到意外。不要寫成繞過權限、偷資料、自動對外人發文的流程。

### 4. 用他會講的話測

寫 2～3 句真實會出現的話。含一句應該觸發、一句不該觸發（用了相近的詞，實際要做別件事）。

有條件的話：同一句話，帶技能跑一次、不帶技能跑一次。產出差在哪裡寫下來。差不出來，這份技能還沒有教到東西。

主觀產出（文案語氣）用人看。客觀產出（檔案、欄位、結束碼）用命令看。

### 5. 從失敗改，不要從想像加字

使用者指出哪一次不好，先問「技能哪一句讓模型做了這件事」。改那一句的原因，讓模型理解為什麼，少寫全大寫的永遠／絕不。

技能要能用在很多句不同的話上。不要為了通過眼前兩個例子，把步驟寫死成那兩個例子。

同一件重複勞動（轉檔、組 JSON、算核對碼）出現在每一次測試裡，就把那件做成 `scripts/` 裡的一支小程式，技能改成呼叫它。

## 篇幅

`SKILL.md` 正文控制在人可以一次讀完。再長就拆 `references/`，並在正文寫「何時去讀哪一份」。

名稱加描述隨時可能被放進模型的可用技能清單，保持短。

## 與「送提示詞」的差別

提示詞活在一則聊天裡。技能活在檔裡：有觸發、有步驟、有驗收、有替代、有紅線。下一輪換模型，檔還在。

## 驗收

- 資料夾存在，內有 SKILL.md，YAML 有 name 與 description。
- description 含觸發場合。用 2～3 句測試話，至少一句該觸發、一句不該。
- 每步有「怎樣算做對」。
- 沒有絕對路徑、沒有別人的帳號、沒有內部才懂的命令名；有的話已改成替代段。
- 使用者能指出這份技能對應哪一次實跑。
