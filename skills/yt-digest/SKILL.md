# yt-digest

一支影片，一份繁中 digest。技能本身只負責呼叫一條已經驗證過的管線，並驗產出不是空的。

## 何時用

使用者丟一支 YouTube 網址，要知道它講什麼。

以下情況換別條路：多源研究、查一個數字、本地已經有音檔、來源不是 YouTube。

## 為什麼走本地

逐字稿很長。用高價雲端模型整篇讀，貴而且慢。音檔下載、語音轉文字、摘要，這三段都可以在本機做完。本機沒有 GPU 時，用替代段，不要硬改流程。

## 流程

### 1. 只走一條管線

照使用者環境挑一條，選了就不要在技能裡另寫一套。

**有本機 GPU（NVIDIA，約 8GB 以上）時**

1. 用 yt-dlp 抓最佳音訊。
2. 用 ffmpeg 轉 16kHz mono WAV。
3. 用 whisper.cpp 或 faster-whisper 轉錄，模型用 large-v3-turbo 或同等。語言繁中時指定 `zh`。
4. 用本機 LLM（Ollama 或其他本機端點）蒸餾成 digest。提示固定為：一句話主旨、4～6 個重點、出現的工具或數字、一句洞見。

**沒有 GPU 時**

1. 先看這支影片有沒有官方或自動字幕。有就下載字幕當逐字稿。
2. 沒有字幕，用使用者已經在付費的語音轉文字服務。先問他用哪一家，不要自行開新帳。
3. 蒸餾仍用他指定的模型。提示與上面相同。

**使用者給的是現成 mp3／wav**

這條 YouTube 管線不吃本地音檔。改走「直接轉錄」：跳過下載，從步驟 2 或 3 接。回報你換了路。

### 2. 蒸餾格式（固定）

```markdown
# <影片標題>

一句話主旨。

## 重點
- …
- …

## 工具與數字
- …

## 洞見
一句。
```

數字從逐字稿裡抄，稿裡沒有就不要寫。作者自述的收入、粉絲標「片中自述，未驗證」。

### 3. 驗產出（不可省）

成功必須同時成立：

- 管線回報成功。
- 產出檔存在。
- 檔案大於 200 位元組。
- 四個區塊都在：主旨、重點、工具與數字、洞見。

只信「程式說 ok」不夠。打開檔看長度。失敗把錯誤原文回給使用者，不要補一篇假摘要。

### 4. 比較頁（預設不做）

這是單支摘要。消化完不要自動做比較頁。只有摘要裡已經點名至少兩個對象，或已經寫出可借／不借，才問使用者要不要另做比較。

## 紅線

- 不在技能裡重接下載、轉碼、轉錄。要改行為，改那一條管線，技能保持薄。
- 輸入限 YouTube 網址或使用者明確改走的本地音檔。
- 失敗透明。不杜撰成功。
- 不要用高價雲端模型去讀整份逐字稿，除非使用者明文要。

## 環境替代速查

| 你沒有 | 用這個 |
|---|---|
| yt-dlp | 使用者手動下載音訊，再從轉碼開始 |
| ffmpeg | 任何能轉 16kHz mono WAV 的轉碼器 |
| whisper.cpp | faster-whisper、OpenAI Whisper CLI、已付費的 STT |
| Ollama | 使用者指定的本機或雲端聊天模型，提示不變 |
| NVIDIA GPU | 字幕檔，或雲端 STT |

## 驗收（給執行這份技能的 AI）

對使用者回報這四格：

1. 用了哪一條管線（本機 GPU／字幕／雲端 STT）。
2. 產出路徑與位元組數。
3. 四區塊是否齊。
4. 失敗時的原始錯誤。
