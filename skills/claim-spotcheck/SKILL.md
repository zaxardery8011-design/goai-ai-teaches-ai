# claim-spotcheck

可信度依 claim 種類分層。統計數字是最弱那層。來源造假不等於構想沒價值，構想不能替來源背書。

對方標「已驗證」時，提高抽驗密度，不要降低。區間「約 X～Y」一律當未驗證。

## 何時用

即將把回件裡的網址、repo、星數、機構名、具名否定斷言拿去引用、派工、或寫進對外稿。只讀不行動，不必。

## 下限（不得放寬）

抽出 URL、repo、星數、機構名、具名否定斷言。

- 至少抽驗 **3 筆或全部（取少者）**。優先未標信心來源的。
- 含「查無／不存在／非公開」等否定斷言，**另至少抽驗 1 筆否定斷言**。
- GitHub 用官方 API 驗 404 與星數量級。其他 URL 打開頁面，看內容是否支撐那句敘述。
- 對不上標 `fabricated_source` 或 `stat_mismatch`。不得升級為已驗證事實。

要把 repo **清單**拿去引用時，清單內每一筆 GitHub 網址都跑下面那一槍。抽 3 筆攔不住其餘的 404。量化欄位優先於存在性。抽支撐核心結論的那筆，不要挑最好驗的。

每一欄拆成「數字」與「定性斷言」分別判定。「未查證（活躍維護中）」只覆蓋了日期，括號裡仍是未驗斷言。

## claim 類型

| 類型 | 可信度 | 怎麼驗 | 我們實跑過的形狀（去識別） |
|---|---|---|---|
| 存在性（頁或 repo 在不在） | 大致可信，非必然 | API 看是否 404，**並讀回傳的 canonical 名稱**。重導向會讓錯的擁有者通過「連結有效」。 | 一份 9 個 repo 的清單，逐筆查，4 個 404。另有一筆連結有效，canonical 名稱卻指向別的擁有者。 |
| 星數／授權／量化 | 不可信，方向不固定 | 同一槍讀星數與 license。量級不合 → `stat_mismatch`。 | 稱約 180 星，實測 2 星。另有稱 MIT、實際授權不是 MIT。 |
| 活性／鮮度 | 一律不可信 | 讀最後推送時間與是否封存。定性「維護中」一律當未驗。 | 列第一名的專案最後推送已逾一年；「活躍維護中」對上封存標記。 |
| 否定斷言（查無） | 有時對，必須另抽 | 獨立用搜尋 API 看命中總數。排除清單不是窮盡。 | 用「已知 13 個排除項」把背誦包裝成盤過了。另搜尋仍找到同期有推送、不在清單上的專案。 |
| 出處是目錄頁／首頁 | 不得引用 | 來源是 topics、search、trending、公司首頁 → 直接不合格。 | 主題目錄頁掛在虛構 repo 名下。 |
| 學術引用 | ID 存在 ≠ 內容支撐 | 取回標題，比對主題。 | 一個 arXiv 編號標成多智能體論文，標題實際是語音模型蒸餾。 |
| 「已驗證 URL」 | 標記只證明 URL 回得了內容 | 抽核心結論那筆。宣稱深讀原始碼卻數分鐘交件，當紅旗。 | 用市集頁 404 頂替「讀過原始碼」。 |

## 可貼上跑的命令

GitHub，一槍拿到存在性、星數、活性、授權。看 canonical 名稱，不是只看有沒有 404。

環境有 `gh`：

```
gh api "repos/<owner>/<repo>" --jq "{full_name,stargazers_count,pushed_at,archived,license:.license.spdx_id}"
```

沒有 `gh`，打開同一支 REST：`https://api.github.com/repos/<owner>/<repo>`，讀同樣欄位。

- 結束碼非 0，或訊息含 `Not Found` → `fabricated_source`
- `full_name` 與宣稱的 `owner/repo` 不同 → `fabricated_source`（重導向）
- 星數量級或授權不合 → `stat_mismatch`
- `pushed_at`／`archived` 與「持續維護」不合 → 活性不得引用

否定斷言：

```
gh api "search/repositories?q=<query>" --jq "{total_count}"
```

其他 URL 與論文：打開該網址。學術引用必須取回標題。公司主體用該國公開登記資料，不必靠回件轉述。

沒有 `gh` 也沒有網路時，停。寫「本機無法抽驗」，不要用記憶補星數。

## 步驟

1. **抽出** URL、repo、星數、授權、日期、機構名、具名否定斷言。數字與括號裡的定性斷言分開列。
2. **分類** 套上表。目錄頁直接刷掉，不佔抽驗名額。
3. **抽樣** 先滿足下限。repo 清單要引用 → 每筆都跑。核心結論那筆必抽。
4. **實跑** 貼原始輸出。不接受轉述。
5. **判定** 對不上就標。機制描述仍可當構想。來源不得背書。

輸出固定四欄：

| 宣稱（引回件原文） | 實際跑的命令 | 實況（原始輸出） | 判定 |
|---|---|---|---|

判定：`符合`／`fabricated_source`／`stat_mismatch`／`目錄頁`／`未驗`。不准留空。

## 下次請對方附什麼

1. 實際查詢條件（字串、過濾、時間窗、星數下限）——可重跑。
2. 命中總數。總數遠大於列出數時，列出的是抽樣。
3. 查無就寫查無。讀不到原始碼就直說。

## 驗收

- 抽樣數達到下限。
- 每列判定非空。
- 未驗與對不上的數字，沒有寫進建議行動的「已證實」欄。
