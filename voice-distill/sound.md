# 音色：用開源專案學會用你的聲音唸稿

以下步驟是我們實際跑過的。工具以當時能跑起來的開源專案為準。新的專案出來，先核對它的 README 與 issue，再決定要不要換。換了就整條換，不要舊權重配新流程。

## 做什麼

1. 錄自己的聲音。
2. 人核對逐字稿。
3. 選一個成熟的開源語音專案。
4. 切句、訓練或微調。
5. 用沒在訓練裡的句子做試聽。一次只給人一份檔，每段標明是哪一個模型。

## 要什麼素材

- 乾淨錄音。環境噪音低、離麥克風距離固定。唸稿比閒聊好對。
- 逐字稿。以人聽過的為準。自動語音辨識只是草稿。
- 實測規模：日常對話切片約 20 分鐘（一百多段）可以做第一版。另一次專門唸稿，收人核過的約 3 分鐘新段，用來補台灣口音。微調包大約 95 段、約 11 分鐘，也夠做一輪 flow 微調。
- 稿與音對不上超過三句：停。不要用「聽起來差不多」進訓練。我們有一輪因此整輪沒訓。

## 用什麼開源工具（實跑過的）

### GPT-SoVITS

- 做什麼：克隆音色、微調、推論唸新稿。
- 我們做過：官方整合包安裝、CUDA 能跑、錄音切成一百多段、兩段式微調（GPT 約 10 epoch、SoVITS 約 8 epoch）、輸出試聽。
- 硬體：消費級 NVIDIA，約 8GB 顯示記憶體那一檔。
- 時間：環境與資料整理以小時計。微調看資料量，消費卡上數十分鐘到數小時。
- 難度：★★★★☆
- 限制：後來用舊權重唸新的口語稿，自動辨識字錯率一次約 36%，一次約 78%。聲紋分數高、字唸不準，兩件事要分開驗。台灣口語不是它的強項。

### BreezyVoice（聯發科，台灣華語）

- 做什麼：台灣口語底模，再用自己的錄音微調。
- 我們做過：在資料中心級顯示卡上把訓練環境修到通過前置檢查；特徵 95 段；因兩句超過原本文本長度上限，訓練集從 81 降到 79；跑完 5 個 epoch，驗證損失從約 0.63 降到約 0.56；之後做五句零樣本對微調的盲聽包。
- 硬體：微調我們跑在資料中心級顯示卡。推論短句可以在 CPU 上跑，慢：一句約 4 秒的音，推論牆鐘約 70～110 秒。有顯示卡會快很多。
- 時間：環境依賴是大頭（套件版本鎖死、缺 wheel，修了兩輪）。環境好了之後，特徵約 1 分鐘、5 epoch 約數分鐘（資料中心卡）。消費卡請另估。
- 難度：★★★★★（難在環境與「選對底模」，訓練本身不一定長）
- 限制：依賴組合換 Python 版本就可能沒有現成套件。文本過長的句子會被原專案過濾，訓練程式若要求筆數對得上清單，會整輪中止。

兩個都做過之後的方向：台灣口語唸稿，以 BreezyVoice 為準。GPT-SoVITS 留在要對照、或只有 NVIDIA 消費卡的時候。人已經定案用新底模，就不要再拿舊權重交差。

其他專案（CosyVoice、SoVITS 舊版、雲端克隆服務）我們沒有在同一條驗收下跑完，本檔不教。要換，先走「搜成熟做法」那一條教訓。

## 步驟（給執行的 AI）

1. 問使用者：有沒有 NVIDIA、有沒有其他廠牌的顯示卡、錄音在哪、逐字稿人核過沒有。
2. 沒有人核稿，先做核稿。自動辨識與原稿並列，人聽第幾句、定哪一版。三句不定，停。
3. 去程式託管網站打開該專案的 README、安裝 issue、授權。把要用的那一條安裝命令給使用者看過再跑。
4. 切 3～10 秒、單聲道。取樣率跟該專案要求走（常見 16k 給辨識、32k 給訓練，以 README 為準）。
5. 訓練。記錄 epoch、耗時、顯示記憶體峰值、驗證損失。
6. 試聽。一次一份。訊息裡寫「第 1 段是零樣本、第 2 段是微調」。不要把三個版本接成一支讓人猜。
7. 字準與像不像分開打分。字準可用自動辨識對稿（只當指標，耳聽才算）。像不像用人盲聽。

## 驗收

- 逐字稿有人核紀錄。
- 試聽檔存在、能解碼、每段標得清。
- 字錯率與聲紋分數分開寫。沒有耳聽，不宣稱「可以用了」。
- 使用者聽得懂要對哪一段。
