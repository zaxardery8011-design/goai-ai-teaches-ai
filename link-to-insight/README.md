# 丟一個連結，AI 幫你看懂

給 AI 一個網址。它回你：這頁在說什麼、數字站不站得住、對你有沒有用。看與分析。不自動留言，不自動發文。

## 先問使用者

1. 網址是哪一個？
2. 這頁打開要不要登入？
3. 他想帶走什麼：摘要、可借／不借、還是對帳（文章數字對公開文件）？

問完再動手。

## 四種頁，四條路

### A. 公開網頁、公開文章

用你現有的抓頁工具打開。讀正文，不要只讀標題。

報告最少有：

- 來源與範圍（讀了哪些區塊、讀了幾成）
- 一句話定位
- 文章自己的結構
- 數字：哪裡來的、你有沒有打開原始文件核過
- 對使用者可能有用的判斷
- 沒核到的標未驗證

實例形狀（去識別）：一篇把某家公司講成「五千億保單」的財經文。拆開看，那是三筆還沒加總的帳——別人打算募的資金、買雲端容量的承諾、某園區租約擔保上限。三筆都不是已發生的虧損。文章乘出來的數字，原始新聞稿與季報對不上。方法：打開原文、打開它引用的 10-Q／新聞稿／當事人貼文，對不上就寫對不上，不補金額。

### B. 要登入的頁（社群個人頁、後台、會員文）

用**使用者自己的瀏覽器**。他已經登入的那一個。

可用的做法，擇一，選他已經有的：

| 環境 | 怎麼做 |
|---|---|
| 電腦上的 Claude Code，裝了官方 Chrome 擴充 | 在他的 Chrome 開新分頁操作。先看他現有分頁，不要搶正在用的。 |
| 其他能控瀏覽器的助手（Playwright、Chrome DevTools Protocol） | 接到他啟動、而且已經登入的那顆瀏覽器。連線埠與啟動方式問他。不要自己新開一個沒登入的視窗然後猜帳密。 |
| 只有聊天、沒有瀏覽器工具 | 停。請他改用有瀏覽器的那一側，或自己把頁面另存給你。 |

登入頁、驗證碼、雙因素：停，等人。不要輸入帳密。不要把 cookie 抄出來。

捲動抓清單時，抓完先看最早一則的日期。粉絲很多、最早一則卻是上個月，多半捲太快、少抓了一大半。連續多次沒有新則才停，每次間隔給頁面時間。

### C. YouTube

走 `skills/yt-digest`。這裡不重寫轉錄流程。

### D. 長文庫、電子報、公開資料庫

能用官方 JSON／archive 端點就用，比一頁頁點穩。抓到的篇數對最早日期。對不上就標「可能不是全量」。

全文很多時，分組讀：固定欄位（開場、骨架、導流、主張各附一句檔內原話）。再綜合。再找一輪挑錯，專門抓「一律／每篇／固定」。絕對詞改成實際比例。

## 創作者連結（多頁、要判斷可借不借）

進 `PLAYBOOK.md` 的九個切入點。報告順序固定：

來源範圍 → 一句定位 → 內容系統 → 產文邏輯（比例，不用絕對詞）→ 導流與變現（自述數字標未驗證）→ 可借／不借（各附理由）→ 未解。

可借優先：讀者能拿走的形狀。選題法、一則一想法、先說出讀者的反駁。

不寫進對外稿的：沒出處的收入、留言門檻換教學、把角色 IP 當自家儀表板、誘導留言再把人趕進私訊領提示詞。

## 紅線

- 只看與分析。填草稿可以，送出鍵留給人。
- 不自動按讚、不自動追蹤、不自動回覆。
- 對方自述的粉絲、訂閱、收入一律未驗證。
- 原始擷取只放使用者指定的研究資料夾。對外改寫用自己的話。逐字引文短。
- 編號打錯被導到登入頁，是編號錯，先當操作錯誤，不要當成權限問題硬登。

## 驗收

- 報告寫得出讀了什麼、沒讀什麼。
- 每個關鍵數字能指回一個你打開過的來源，或標未驗證。
- 要登入的頁，全程用他的瀏覽器；過程沒有送出公開動作。
- 可借／不借各至少一條理由。做不到就寫「這次只做摘要，還沒到借鏡」。
